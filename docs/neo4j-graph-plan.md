# 知识图谱接入实施计划

设计依据：[neo4j-graph-design.md](neo4j-graph-design.md)。用户已确定技术方案并要求完成接入，本轮按既有授权持续执行。

1. Python：先增加隔离/来源/任务失败反例，再实现 LlamaIndex 真实抽取、来源局部图节点、Neo4j staging/发布/删除、异步构建状态及内部 API。固定作用域 Cypher、有界进程与响应，不执行模型 Cypher。
2. Java：先增加请求层与 engine 合同反例；生成活动来源快照、校验 Python 图响应、接异步状态、版本与删除生命周期。原接口兼容；当前仅保留Engine/Neo4j实现；图谱抽取失败不回滚正确的向量上传。
3. 前端：按最终 Java VO 扩展 ENTITY/RELATED_TO、安全类型兜底、多来源节点和关系详情、构建状态与轮询、失败保留已有图。权限、取消请求、KB 切换过期响应均覆盖。
4. 集成：配置模板/私有 Compose/Nacos 用途注释、精确依赖锁、版本、文档；本地 Python/Java/前端测试和安全检查；独立 Review 覆盖身份与生命周期。
5. 实际验收：小型合成文档、Neo4j/Qwen 真实构建、跨文档证据、租户/KB、删除和换版、既有 Qdrant 检索；浏览器节点/边与来源操作。镜像发布与 NAS 部署读回独立取证。
6. 交付：仅本轮范围 commit，合入并推送 main，远端包含关系/CI读回后清理功能分支；个人不创建 test/preprod，美联不动。

## 风险重点

- 相同名字跨租户/KB/chunk 合并和覆盖来源。
- 删除、换版和迟到任务导致幽灵关系。
- 错误空图、抽取超时、重启与队列满被误报成功。
- 仅有 graph:view 的用户读取未获准完整文档内容。
- 模型输出控制字段、HTML、任意 Cypher 与过大响应。

工作进度及本机验证证据放在 Git 外私有目录，公共文档不保存凭据或开发机路径。
