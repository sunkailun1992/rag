# 图谱批量原文抽取纠正修复

## 问题与目标

调用方为文档图谱管理页，仍通过 Java 权限门面访问原有构建、状态与查询接口。批量抽取中，模型可能把不连续的标签、范围或状态拼成实体名；现有原文守卫正确拒绝，但全部原文错误被强制交给仅能修正标点差异的局部计划。无法建立局部计划时直接终止，使完整重抽反馈不可达。

本次恢复有界的完整候选重抽。保留同支持子句的局部修复快路径；计划不适用时重新阅读完整当前切片，不把旧三元组冻结为事实。每个候选独立通过原有结构、长度、数量、原文与作用域守卫。切片累计最多三个模型请求，包括局部修复；网络临时恢复与纠正共用该预算，不丢弃失败切片，不逐条过滤非法关系，不允许非空错误后以空图成功。

## 动作与状态事实

实际批量回包还出现一元动作被写成「主体、完整动作谓词、空对象」的情况，连续纠正仍会复用该错误表示。抽取合同因此明确：原文已经给出的完整动作、要求或状态可以作为 `objectQuote`，谓词使用短的语义关系标签，保留动作里的否定、程度、条件和模态。不能凭空补对象，也不能程序裁分词句来假装模型已经正确抽取。合成示例使用工作场景，不嵌入业务原文。

这只是将原有事实完整表达为三元组，所有字段仍需非空、两个端点仍需连续原文匹配。上游返回了严格schema请求仍不符合字段长度约束的实际响应，因此应用层完整校验继续保留，不把供应商的结构约束当成数据真实性或格式正确性的唯一凭据。

## 模型传输故障

大批量真实诊断在一百余个合法切片后重现单请求超时，未收到模型回包。原工作进程将模型超时、HTTP拒绝与其他未知异常统一归为 `GRAPH_BUILD_FAILED`，既缺少准确原因，也会把一次暂时故障升级为整批失败。

模型边界现在生成固定、脱敏的模型错误类型。短暂超时、明确网络中断、429及500/502/503/504与所有语义纠正共享单片三个HTTP请求，不在底层HTTP函数内增加隐藏循环。重发保留完全相同的完整/slot请求模式；等待可取消，原总deadline继续约束。鉴权、配置、证书、协议、超大响应、无效外层JSON以及非模型源码错误不重试。

错误桥接只接受固定类型、错误码、配对reason和可信来源hash。HTTP层只为拒绝附加真实整数状态，不保留地址、头或正文；任意异常恰好含相同文本不能冒充模型错误。未知故障仍明确失败；内部诊断仅保留固定阶段、固定异常类别及受限的代码文件/函数/行号，不记录异常原文、源码行、局部变量或输入。

## 批量存储与查询预算

实际全量构建已完成模型抽取并写入全部来源切片，随后在 Neo4j 批量持久化阶段发生事务超时。构建存储误用了交互查询的三秒事务预算；此前小样本通过不能证明大批量写入完成。

构建子进程的 Neo4j store 使用独立的 `RAG_ENGINE_GRAPH_STORAGE_TIMEOUT_SECONDS`，默认30秒、配置范围1至60秒，涵盖构建去重查、128条分批写入和持久化读回。页面查询、提交及控制面继续使用原查询预算；父进程从入队起的构建总deadline仍覆盖全部阶段并可杀死/回收worker。该参数不增加容器资源，不增加模型重试，不允许绕过读回、来源核对和原子发布。

故障诊断将构建输入、来源读取、索引构建、持久化读回、来源复核和资源清理分开。子进程非零退出只记录受控退出码、信号及输出字节数；未知异常只提供固定类别和受限代码栈元数据。清理失败不能覆盖更早的主异常，不能为了诊断把正文、查询参数、模型响应或凭据写到日志。

## 逐来源断点复用

全量任务还暴露了另一类独立故障：模型在同一来源的不同请求中会输出不同候选，某片连续三次未通过原文校验就取消整个批次；此前已通过的结果没有保留，下次会重新调用全部来源。单次定向成功不能据此宣称整批稳定。

构建在原官方逐片提取器外增加已验证三元组检查点，持久在现有 Neo4j。只保存完整通过结构、数量、字段和原文守卫的原始三元组，不保存拒绝候选、模型原始回包、序列化 TextNode 或旧 generation 的实体 ID。复用键覆盖租户、知识库、完整活动来源身份、原始正文 SHA、模型/供应商身份、提示词/schema/守卫协议和抽取参数；不包含密钥或 buildId。

命中仍核对完整 envelope 和当前来源，以当前可信节点重新构造实体/关系并重跑原有守卫；后续作用域变换继续生成本任务 ID。缓存失效、损坏、超限或不可用只触发重新抽取，不产生空图成功。失败片不进入检查点，已经通过的其他片可在后续任务复用；单片原有三个模型请求与整次构建 deadline 均不变。任务仍需所有活动来源通过、完整存储读回及原子发布才为成功。

检查点缺省24小时过期，单条最多64 KiB、全局最多10000条及128 MiB逻辑载荷；不增加容器内存。只有非空且完整验证的候选进入检查点，合法空结果仍走原提取流程，不能用空值替代失败。读写须检查当前任务及文档请求版本、删除屏障 epoch；写入与删除使用同一屏障的锁序，删除在同事务清理该租户文档的所有配置/知识库检查点。迟到旧任务不能在删除后重新创建记录。缓存只改善重试成本，不授予发布权限，不替代 Qdrant ACTIVE 来源校验或最终发布 fencing。

检查点生命周期跟随 PropertyGraphIndex 的同一个异步事件循环：在提取器的批量 `acall` 中打开，在所有任务完成或取消后关闭，避免跨 `asyncio.run` 复用驱动。资源清理不得覆盖原始错误。

## 验收标准

- 合成HTTP链路覆盖瞬态恢复、永久拒绝、slot模式保持、三次总上限、取消与deadline，以及worker/parent诊断注入拒绝。
- 合成复现覆盖非连续名称、双端改写及跨字段来源，证明合法后续候选可到达。
- 局部修复仍绑定当前来源和计划；失败回到完整重抽时不携带共享可变计划。
- 验证请求上限、错误空结果、并发取消、错误映射不被机械修复为事实，以及原文/日志/隔离边界。
- 检查点覆盖命中零模型调用、当前 generation 重建、来源/模型/提示词变化失效、损坏回退、失败不缓存、容量/过期、删除/旧 epoch 和取消等反例。
- 在实际文档全体活动切片上完成任务，读回已发布图谱及来源身份。
- 比较完整 Qdrant payload 与向量指纹，保证抽取修复没有修改权威文档或向量。
- CI、镜像发布、运行版本和真实文档验收分别记录；小样本与离线测试不代替全量构建。

## 开发与运行

核心实现在 `engine/src/rag_engine/graph_extract.py`，受限引用计划继续由 `graph_schema.py` 提供。HTTP 路径、权限码、租户传递、Qdrant 模型/维度、Neo4j 原子发布、删除屏障及任务 deadline 保持原有协议；不新增业务表；新增的构建存储事务预算与交互查询隔离。

本批只提升 Python 引擎补丁版本，Java 制品不变。通过锁定依赖的 pytest、静态检查、跨语言协议及独立反例验证后，构建不可变镜像。部署仅更新引擎镜像，读回配置及容器限制，再执行真实构建和只读验收。回滚使用此前镜像摘要和私有 Compose 备份。

## 判断边界

名称匹配原文不证明任意模型关系都正确；颜色、范围和条件对应关系仍需按原文核查。重抽允许纠正首次候选本身的错误，不能以保留旧候选数量或冻结已经出现的词宣称语义真实性。模型在有界请求后仍不满足合同则任务明确失败，失败 generation 不对外发布。
