# 图谱批量原文抽取纠正修复

## 问题与目标

调用方为文档图谱管理页，仍通过 Java 权限门面访问原有构建、状态与查询接口。批量抽取中，模型可能把不连续的标签、范围或状态拼成实体名；现有原文守卫正确拒绝，但全部原文错误被强制交给仅能修正标点差异的局部计划。无法建立局部计划时直接终止，使完整重抽反馈不可达。

本次恢复有界的完整候选重抽。保留同支持子句的局部修复快路径；计划不适用时重新阅读完整当前切片，不把旧三元组冻结为事实。每个候选独立通过原有结构、长度、数量、原文与作用域守卫。切片累计最多三个模型请求，包括局部修复；不增加网络重试，不丢弃失败切片，不逐条过滤非法关系，不允许非空错误后以空图成功。

## 动作与状态事实

实际批量回包还出现一元动作被写成「主体、完整动作谓词、空对象」的情况，连续纠正仍会复用该错误表示。抽取合同因此明确：原文已经给出的完整动作、要求或状态可以作为 `objectQuote`，谓词使用短的语义关系标签，保留动作里的否定、程度、条件和模态。不能凭空补对象，也不能程序裁分词句来假装模型已经正确抽取。合成示例使用工作场景，不嵌入业务原文。

这只是将原有事实完整表达为三元组，所有字段仍需非空、两个端点仍需连续原文匹配。上游返回了严格schema请求仍不符合字段长度约束的实际响应，因此应用层完整校验继续保留，不把供应商的结构约束当成数据真实性或格式正确性的唯一凭据。

## 验收标准

- 合成复现覆盖非连续名称、双端改写及跨字段来源，证明合法后续候选可到达。
- 局部修复仍绑定当前来源和计划；失败回到完整重抽时不携带共享可变计划。
- 验证请求上限、错误空结果、并发取消、错误映射不被机械修复为事实，以及原文/日志/隔离边界。
- 在实际文档全体活动切片上完成任务，读回已发布图谱及来源身份。
- 比较完整 Qdrant payload 与向量指纹，保证抽取修复没有修改权威文档或向量。
- CI、镜像发布、运行版本和真实文档验收分别记录；小样本与离线测试不代替全量构建。

## 开发与运行

核心实现在 `engine/src/rag_engine/graph_extract.py`，受限引用计划继续由 `graph_schema.py` 提供。HTTP 路径、权限码、租户传递、Qdrant 模型/维度、Neo4j 原子发布、删除屏障及任务 deadline 保持原有协议；不新增业务表或配置参数。

本批只提升 Python 引擎补丁版本，Java 制品不变。通过锁定依赖的 pytest、静态检查、跨语言协议及独立反例验证后，构建不可变镜像。部署仅更新引擎镜像，读回配置及容器限制，再执行真实构建和只读验收。回滚使用此前镜像摘要和私有 Compose 备份。

## 判断边界

名称匹配原文不证明任意模型关系都正确；颜色、范围和条件对应关系仍需按原文核查。重抽允许纠正首次候选本身的错误，不能以保留旧候选数量或冻结已经出现的词宣称语义真实性。模型在有界请求后仍不满足合同则任务明确失败，失败 generation 不对外发布。
